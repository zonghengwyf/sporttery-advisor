# 自动出票追踪页面需求文档

> 来源：产品方 2026-07-30 需求讨论
> 对应文件：`frontend/src/views/BetRecord.vue`（自动出票 tab）

---

## 一、核心信息展示需求

用户必须能在不翻页的情况下轻松获取以下所有数据：

### 1.1 整体统计
- 总命中率（串子方案维度）
- 单场预测命中率（leg 维度，与串子结果无关）
- 总 ROI、总盈亏
- 运行次数、已同步次数、跳过次数

### 1.2 分类准确率（可点击筛选历史记录）
- 按方案类型：稳健 / 均衡 / 博高赔 / 比分
- 按模型：各 LLM（包含混合/单模型区分）
- 按串数：2串1 / 3串1 / 4串1 等

### 1.3 收益分析
- 哪种方案类型带来最高 ROI（不仅是命中率，要看盈利）
- 哪种模型带来最高 ROI
- ROI 为负的方案要有明确标记

### 1.4 预测选项精度分析（选项维度，核心新需求）
统计所有已结算 leg 中各选项的预测准确率：

| 选项 | 预测次数 | 命中次数 | 命中率 |
|------|---------|---------|-------|
| 主胜 | - | - | - |
| 客胜 | - | - | - |
| 平局 | - | - | - |
| 让球主胜 | - | - | - |
| 让球客胜 | - | - | - |
| 让球平 | - | - | - |

**注意**：同一场比赛出现在多个方案里时，只统计一次（去重 by run_id + match_id + pick）。

### 1.5 赛果实际分布（独立于预测）
统计所有已结算比赛的实际结果分布：
- 主胜（H）占比
- 平局（D）占比
- 客胜（A）占比
- 让球相关结果（若有数据）

用于回答"哪种结果最常见"，帮助用户评估模型偏向。

### 1.6 联赛维度准确率（leg 级别）
按联赛统计单场预测命中率，显示样本量。

## 二、数据同步需求

### 2.1 手动同步
- 每条运行记录卡上保留"同步赛果"按钮（当前已有）
- 同步失败时显示错误原因

### 2.2 自动同步
- 定时任务（APScheduler）每日自动同步（待 Phase 5 完善）
- 当前状态在 Zone 1 hero 区展示：已同步 / 待同步 / 跳过 数量

---

## 三、筛选与过滤需求

### 3.1 必须支持的维度筛选
- 按方案类型（稳健/均衡/博高赔/比分）
- 按模型（可多选）
- 按日期（今天/近7天/近30天/全部）
- 按串数（2串1 / 3串1 / 4串1 等）
- 按同步状态（已同步 / 待同步）

### 3.2 筛选后的效果
- 历史运行记录列表按筛选过滤
- 顶部统计区随筛选动态更新（暂不要求，二期）
- 当前激活筛选条件有明确展示，可一键清除（已实现）

### 3.3 每日视图
- 每日数据在历史列表中清晰分组（按日期）
- 能快速看到某天有几条运行、中了几个方案

## 四、图表数据可视化需求

### 4.1 统计区图表（优先级高）
- **选项命中率**：横向柱状图，每行 = 一个选项类型，柱长 = 命中率%，颜色跟随绿/黄/红等级
- **赛果分布**：3格横排（主胜/平局/客胜），大数字显示%，副标签显示场数
- **方案 ROI 对比**：横向柱状图，正数绿色，负数红色，显示 ROI% 和盈亏金额
- **模型命中率对比**：同方案 ROI 形式

### 4.2 趋势图（优先级中）
- 命中率随时间的趋势（每日或每周汇总）
- 需要 ECharts 折线图

### 4.3 技术选型
- 已安装 ECharts，可复用 BacktestReport.vue 中的用法
- 移动端优先：简单统计用 CSS 柱状条（更轻量），趋势用 ECharts

## 五、方案详情页评估

### 5.1 现状
当前点击方案卡片会弹出底部 sheet（`sd-sheet`），显示腿详情、赔率、结果。

### 5.2 独立页面的价值评估
**适合独立页面的场景：**
- 需要展示 AI 分析原因（较长文本）
- 需要展示每场比赛的背景数据（赔率走势、伤停信息等）
- 需要支持分享/截图保存
- 腿数多时底部 sheet 需要大量滚动

**结论：建议实现**
- 路由：`/track/runs/:runId/schemes/:planId`
- 页面内容：方案头部（类型/赔率/状态）→ 腿列表（详细数据）→ AI 分析摘要（如有）→ 底部操作
- 当前底部 sheet 可保留，点击"查看详情"跳转到独立页面

### 5.3 实现优先级
Phase 4.5（当前）：独立页面骨架 + 基本腿数据
Phase 5：接入 AI 分析摘要

## 六、数据层补全需求

### 6.1 前端可计算（不需新后端接口）
- ✅ 选项命中率（pickTypeAccuracy）：从现有 leg.pick + leg.won 计算
- ✅ 赛果分布（resultDistribution）：从 leg.actual_result 计算
- ✅ 方案 ROI（schemeRoi）：从 scheme.profit + run.stake 计算
- ✅ 模型 ROI（modelRoi）：同上，按 model_info 分组

### 6.2 需要后端补全（二期）
- leg 级别的赔率数据（已有 leg.odds）
- leg 级别的联赛数据（已有 leg.league，需保证填充）
- 让球市场的 handicap 值（leg.market + leg.handicap 字段）

---

## 七、UX 规范

- 移动端优先，所有交互元素最小 44×44px
- 空状态：统计区无数据时显示简洁说明行，不显示 N 个重复占位符
- 颜色系统：命中率 ≥60% 绿色、40-60% 橙色、<40% 红色
- 数字字体：使用 `font-num` / `var(--font-disp)` 等项目约定类
- 筛选激活态有明确视觉反馈（primary 色边框/背景）
